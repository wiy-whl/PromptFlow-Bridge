大理 · 设计过程

用户 → 筛选 → 收敛 → 测试 → 架构 / 流程 → 低保真 → 高保真 → 故事板。不编商业数据。

课程项目。主用户是周末第一次来的年轻人。本期只解：打开手机时不知道先看哪一面。高保真可点：index.html

1. 用户：圈进 / 圈出

圈进 18–30，第一次来或只来周末。
已经到大理或出发前一晚。
对文化有一点兴趣，但不是研究者。
圈出 向导 / 徒步 / 摄影团（要地图机位）。
亲子长线（节奏不同）。
要买票下单的人（课程不做支付）。

他们问的只有三句

今天先去哪？要可比较的短卡片
大概要多久？详情里三格信息
看完去哪？相关推荐，不死胡同

2. 需求筛选：只解一个场景

核心场景：到达当天上午，在客栈用 2 分钟决定先看哪一面。不做三日行程、导航、购票。

Must启动能跳过 · 首屏三入口 · 列表能比 · 详情有时长/怎么去 · 看完有下一站
Should想去 + 空状态 · 加载 / 失败
Could搜索、筛选（不作为主路径）
Won't登录、支付、地图、UGC、行程算法、满屏扎染底

3. 方案：留下导览卡片，砍掉另外四条

A 数字展览好看，完不成「先去哪」
B 攻略社区没有内容运营
C 行程生成数据是编的
D 假电商没有真货库存
E 留下：导览卡片 分发 → 列表 → 详情 → 想去。同一套结构走景点 / 文化。

4. 原型测试（5 人，测任务不测好看）

#任务怎样算过
T1这是干什么的？一句话说能说「大理导览」
T2下午想先看湖，点进去≤2 次到洱海详情
T3去洱海要多久、怎么去看见三格，不找很久
T4收入想去，从「我的」找回能原路找回
T5想看懂扎染，点哪走进文化，不进假商店

测完只记原话。没有 5 人表之前，作品集不写效率百分比。

5. User Flow

打开→ 启动 跳过/开始逛→ 首页三入口→ 列表→ 详情三格→ 想去→ 我的

6. 低保真 · 页关系与页内骨架

灰度只看结构。首屏必须看见三个入口。详情页结构复用。

S01 启动
S02 首页
S03 列表
S04 详情
S08 我的

S05/S06 复用列表+详情；带走收在文化详情里，不另开入口；S09 空状态；S10 叠在列表上。

7. 故事板

客栈 · 刷手机

01 卡住收藏了三十篇，仍不知道今天下午去哪。

航拍水面

02 定位这是导览。可以跳过，不必看完开场。

三张入口

03 分发先看湖，还是先看懂当地。

三格信息

04 决策3–4 小时，东门约 20 分钟。去得成。

Toast

05 收着加入想去。不用现在出发。

我的列表

06 找回回来找得到。空页也不像坏了。
